# 永恆北極星｜30 分鐘演講稿
## 版本：秋芸羊本人講得出口版

> 對應 2026-09-20 個人專題報告。  
> 這份不是主持人台詞，也不是企業簡報稿。講者可以停頓、改口、笑一下，不需要每頁都講得像廣告。  
> 千題版依照「新版完成」情境預寫；最後題數、模型、部署與測試結果，請在上台前用實際版本替換。

# 先記住一件事

這場有半小時，但不代表要連續講半小時。

建議：
- 純講解約 22～24 分鐘。
- LINE 實機展示約 4～5 分鐘。
- 中間停一下看畫面、喝水、等回覆，剩下自然會補滿。
- 不需要故意找同學互動，也不用一直問「大家覺得呢」。

講話風格：
- 句子短一點。
- 想到哪裡就接哪裡，但不要跑出主題。
- 可以吐槽自己，別一直貶低作品。
- 技術名詞講完，馬上補一句白話。

## P05｜它現在會什麼？
**時間：04:30–06:00**

### 投影片
1. 直接問
2. 挑戰／出題
3. 導引式學習

### 講稿

現在主要有三種玩法。

第一個就是最普通的，直接問。

像「黑洞會蒸發嗎」、「為什麼啟明星跟長庚星是同一顆」，都可以直接問。

第二個是出題。這部分用固定題庫，不是讓 AI 每次臨時亂生一題，所以答案不會今天 A、明天突然變 C。

第三個是導引式學習。

如果使用者根本不知道該問什麼，就可以先選一條路線，慢慢往下看。

這三個功能我覺得比單純的 FAQ 好玩一點，因為不是只能問完一題就結束。

## P07｜第一次把自己做的 Bot 問倒
**時間：07:15–09:00**

- 「你知道卡爾薩根是誰嗎？」

結果：
「欸，不知道」

### 講稿

我那時候測試，先問它：

「你知道哈雷彗星以前差點把大家嚇死嗎？1910 年那次。」

我想說，好吧。

又問它：

「那你知道卡爾薩根是誰嗎？」

還是不知道。

我就想，欸，這知識範圍有點窄耶。

雖然報告完之後我搞不好也不會天天打開來用，但至少現在自己測的時候，我不想每問兩句就碰到牆。

所以就一路加下去了。

順便說一下，1910 年不是哈雷彗星真的差點撞毀地球，而是當時彗尾成分和媒體報導引起了末日恐慌。

這種「以前的人怎麼會相信這件事」的故事，我反而覺得很好玩，所以也想放進題庫。

## P12｜橘色草地跟白色草地
**時間：13:45–15:30**

### 投影片
橘色草地：
「可以，但要看吸收什麼光」

白色草地：
「先別急，能量帳先算」

### 講稿

這邊是我自己最喜歡的一塊。

因為我在《無人深空》最喜歡橘色草地跟白色草地，所以乾脆把植物顏色全部整理一輪。

不是只有綠色。

紅、橘、黃、紫、藍、黑、白、銀色、虹彩，全部都可以問。

重點不是替每個顏色找一個很帥的理由，而是看它怎麼吸光、反光，還有最後能不能把能量收回來。

橘色還算比較直覺。

白色就麻煩了。

如果表面看起來很白，代表很多可見光被反射，那它到底剩多少能量可以用？

可能是表面白、下面還有吸收層，也可能有其他營養來源。

但這些都不能一句「外星生物嘛」就帶過去。

## P13｜科幻裡的人類光合作用
**時間：15:30–17:00**

### 投影片
假設：
1 m² × 1000 W/m² × 6 h × 5%

≈ 258 kcal

### 講稿

我很喜歡拿作品裡的設定來算。

像《銀河騎士傳》裡面的人類可以光合作用。

那我就想，一個人站在光下面，到底能吃到多少太陽？

假設有效受光面積一平方公尺，光照每平方公尺一千瓦，照六小時，再很樂觀地假設最後有百分之五能變成可用的化學能。

算出來大概兩百五十八大卡。

如果拿一天兩千大卡當比較，大概百分之十三。

所以就算這組條件已經對它很友善，還是比較像補充電量，不太像可以完全不吃飯。

而且人又不是只有需要熱量。

蛋白質、礦物質、各種材料還是要來。

這就是我想要的科幻問題：先覺得很帥，再把帳拿出來算。

## P15｜導引式學習
**時間：18:30–20:00**

### 投影片
短講
↓
理解題
↓
複習挑戰
↓
下一階段

### 講稿

如果只有一千題，使用者還是可能不知道要從哪裡開始。

所以後來又加了導引式學習。

一段不要太長，講完就問一題，看有沒有理解。

幾段之後再來一個小挑戰。

而且四條路線的進度分開存。

今天學星星學到一半，跑去看異星生物，之後再回來，不需要全部重來。

這些進度是程式自己記，不是每次叫模型猜「你上次大概學到哪裡」。

這部分我覺得比單純把題庫變大有用。

## P16｜LINE 實機展示
**時間：20:00–24:30**

### 投影片
Demo
1. 問一題
2. 追問
3. 進入學習
4. 出一題

### 講稿

好，這邊就不繼續用嘴講了。

直接看 LINE。

我先問一個普通問題，再追問一次。

接著進學習模式，看它怎麼記進度。

最後再叫它出題。

### Demo 建議

優先用已經測過、一定會成功的題目：

1. 「啟明星和長庚星為什麼是同一顆？」
2. 「那為什麼有時候早上看到，有時候晚上看到？」
3. 輸入「學習」
4. 選一個你已經測過的路線
5. 最後輸入「挑戰」

不要在現場第一次問一個超怪的新問題。

如果模型 API 臨時死掉，就說：

「好，今天宇宙訊號不好。固定題庫跟學習流程不靠模型，我先展示這部分。」

這樣就好，不需要假裝沒事。

## P17｜後端其實怎麼走？
**時間：24:30–25:45**

### 投影片
LINE
→ Webhook
→ 簽章驗證
→ 路由
→ 本機資料／模型
→ Reply API

### 講稿

剛剛看的是手機端。

後面大概是這樣。

LINE 把訊息送到 Webhook。

伺服器先驗證 LINE 的簽章，確定不是隨便有人偽造一包資料丟進來。

再判斷這是一般問題、出題、學習，還是其他指令。

能用本機資料回答的，就不要每次都叫模型。

真的需要模型的問題，才送給目前設定的模型。

最後再透過 LINE Reply API 回去。

中間還有事件去重和排程，主要是避免同一件事被重複處理，或同一個人連續按幾次把狀態弄亂。

## P18｜資料怎麼存？
**時間：25:45–26:45**

### 投影片
知識卡
題庫
導引教材
SQLite 進度

### 講稿

資料大概分成幾種。

知識卡放的是概念和來源。

固定題庫放題目、選項、答案和解說。

導引教材負責順序。

學習進度則用 SQLite 存在伺服器。

LINE 手機本身不會直接去碰 SQLite。

這樣做的好處是，程式知道現在到底在哪個階段，不需要全部交給 AI 自由發揮。

不然它今天心情好讓你過關，明天心情不好又把你退回第一關，就會很麻煩。

## P19｜測試跟限制
**時間：26:45–27:45**

### 投影片
有測：
- 簽章
- 去重
- 路由
- 題庫
- 進度

還不能說：
- 永遠正確
- 永遠在線
- 一定有學習效果

### 講稿

測試的部分，我主要看程式規則有沒有照預期走。

像簽章、重複事件、指令路由、題庫答案、進度保存。

不過這些測試通過，不代表機器人講的每一句科學都一定正確。

也不代表伺服器永遠不會掛。

更不能說有導引學習，就代表學生一定會學得比較好。

那需要真的找人做使用者研究。

所以我比較傾向把「做得到」跟「證明有效」分開。

## P20｜製作上遇到的困難
**時間：27:45–28:45**

真正的問題：
不是「做不出來」

### 講稿

如果要說這次最大的困難，我覺得不是某一個技術卡住。

「這世界上有 Astra 不會的嗎？」

「這個好像也可以加。」

然後題庫越來越大，功能也越來越多。

最後最需要學的，反而是什麼時候該停。

# 老師可能會問

## 1. 為什麼不用 ChatGPT 就好？

因為一般聊天 AI 當然比我這個東西懂得多。

我這個專題做的是 LINE 串接、自己的知識範圍、固定題庫、導引學習和進度保存。

不是要證明我的 Bot 比 ChatGPT 聰明。

## 2. 有自己訓練模型嗎？

沒有。

模型用現成 API。

我做的是資料、流程、題庫、LINE 串接、角色設定和學習狀態。

## 3. 1001 題是什麼意思？

是正式題目和知識卡的總量上限。

為什麼 1001？

因為《一千零一夜》。

真的就這樣。

## 4. 為什麼用 Gemma？

最現實的理由是免費，而且當時 OpenAI 額度不夠。

系統本身有做成可以換供應商，所以之後也可以換別的。

## 5. 你怎麼知道內容是對的？

固定資料會保留來源，也會做人工和程式檢查。

但我不會說完全不會錯。

AI 可能錯，題庫也可能是人寫錯。

所以找到錯誤就要修。

## 6. 這算 RAG 嗎？

舊版比較接近本機知識卡匹配，再把需要的內容交給模型。

有沒有向量資料庫，要看最後交付版本實際怎麼做。

沒有實作的東西我不會硬叫它 RAG。

## 7. NAS 上線了嗎？

依上台當天狀況回答。

還沒：
「目前展示用的是已經測過的電腦環境，NAS 還沒有完成最後驗收。」

已經：
「目前已經搬到 NAS，這次展示也是用那個環境；但我只敢說目前測試正常，不會說永遠不會斷。」

## 8. 都是 AI 幫你做的嗎？

AI 幫很多。

程式和整理資料都有用。

不過題目要做什麼、哪些內容我覺得不好玩、哪裡要再補、最後要保留什麼，這些是我自己一路測出來的。
