# 先記住一件事

這場有半小時，但不代表要連續講半小時。

建議：
- 純講解約 22～24 分鐘。
- LINE 實機展示約 4～5 分鐘。
- 留時間指圖、操作和閱讀回覆。先出聲彩排；這是時間安排，不是已測得的語速。
- 不需要故意找同學互動，也不用一直問「大家覺得呢」。

講話風格：
- 句子短一點。
- 想到哪裡就接哪裡，但不要跑出主題。
- 可以吐槽自己，別一直貶低作品。
- 技術名詞講完，馬上補一句白話。

## P05｜它現在會什麼？
**時間：04:30–06:00**

### 投影片
1. 直接問
2. 挑戰／出題
3. 導引式學習

### 講稿

現在主要有三種玩法。

第一個就是最普通的，直接問。

像「黑洞會蒸發嗎」、「為什麼啟明星跟長庚星是同一顆」，都可以直接問。

第二個是出題。這部分用固定題庫，不是讓 AI 每次臨時亂生一題，所以答案不會今天 A、明天突然變 C。

第三個是導引式學習。

如果使用者根本不知道該問什麼，就可以先選一條路線，慢慢往下看。

這三個功能我覺得比單純的 FAQ 好玩一點，因為不是只能問完一題就結束。

## P12｜橘色草地跟白色草地
**時間：13:45–15:30**

### 投影片
橘色草地：
「外觀看起來橘色，靠哪些光供能？」

白色草地：
「反射很多光之後，還剩多少能量？」

### 講稿

這邊是我自己最喜歡的一塊。

因為我在《無人深空》最喜歡橘色草地跟白色草地，所以乾脆把植物顏色全部整理一輪。

不是只有綠色。

紅、橘、黃、紫、藍、黑、白、銀色、虹彩，全部都可以問。

重點不是替每個顏色找一個很帥的理由，而是看它怎麼吸光、反光，還有最後能不能把能量收回來。

先從橘色看它吸收哪些光。

白色就麻煩了。

如果表面看起來很白，代表很多可見光被反射，那它到底剩多少能量可以用？

可能是表面白、下面還有吸收層，也可能有其他營養來源。

但這些都不能一句「外星生物嘛」就帶過去。

### 備註，不朗讀
逐色機制是有條件的推演，不是已發現的外星植被。科學背景見 REPORT 的 NASA／NASA GISS 來源。頁面使用機制示意或清楚標示的遊戲素材，不製造觀測證據。

## P13｜科幻裡的人類光合作用
**時間：15:30–17:00**

### 投影片
假設：
1 m² × 1000 W/m² × 6 h × 5%

≈ 258 kcal

小字：教學假設，不是人體實驗；以每日 2000 kcal 作比較，約 13%。

### 講稿

我很喜歡拿作品裡的設定來算。

像《銀河騎士傳》裡面的人類可以光合作用。

那我就想，一個人站在光下面，到底能吃到多少太陽？

假設有效受光面積一平方公尺，光照每平方公尺一千瓦，照六小時，再很樂觀地假設最後有百分之五能變成可用的化學能。

算出來大概兩百五十八大卡。

如果拿一天兩千大卡當比較，大概百分之十三。

所以就算這組条件已經對它很友善，還是比較像補充電量，不太像可以完全不吃飯。

而且人又不是只有需要熱量。

蛋白質、礦物質、各種材料還是要來。

這就是我想要的科幻問題：先覺得很帥，再把帳拿出來算。

### 備註，不朗讀
一平方公尺指有效投影面積，不是全身都同時正對陽光。5% 是假設淨效率。兩千大卡是比較基準，不是個人飲食建議。作品與計算分開標記，來源見 REPORT 第7節及參考資料。

## P16｜LINE 實機展示
**時間：20:00–24:30**

### 投影片
Demo
1. 問一題
2. 追問
3. 進入學習
4. 出一題

### 講稿

好，這邊就不繼續用嘴講了。

直接看 LINE。

我先問一個普通問題，再追問一次。

接著進學習模式，看它怎麼記進度。

最後再叫它出題。

### Demo 建議

用同一交付版本事先跑通的題目，不把曾經成功說成現場一定成功：

1. 「啟明星和長庚星為什麼是同一顆？」
2. 「那為什麼有時候早上看到，有時候晚上看到？」
3. 輸入「學習」
4. 選已測過的路線，讀短講、回答一道理解題；時間夠再換路並返回
5. 最後依實際操作退出學習，再輸入「挑戰」，展示固定題與解說

不要在現場第一次問一個陌生問題。單次等待超過 10 秒，判斷是只有模型出錯，還是整個 LINE／伺服器連線失敗。

只有模型 API 暫時不能用、其他連線仍正常：

「好，今天模型沒回來。固定題庫跟學習流程不靠生成模型，我先展示這部分。」

LINE 或伺服器也不能用：

「現在連線沒有跑完，我改播事先錄好的操作。」

沒有同版本錄影：

「我先用流程圖說明。這張是示意，剛剛那次操作沒有成功。」

### 沒有網路時的替代說明

搭配實際已有的圖或錄影操作；不要捏造 Bot 回答。三段各約 60～90 秒，出聲彩排後決定停留長度。

**第一段：一題怎麼回答。**

先看「啟明星和長庚星」這個問題。這裡我想檢查的是，它能不能認出兩個名稱指向同一個核心概念，再說明為什麼出現時間不同。這和只比對到某一個字，就丟一整段不相關的文章，是不同的。

追問時還要看上一題的關係有沒有留下來。但保存學習進度，不代表模型永遠記得全部聊天，所以不能看到一次追問成功，就說它有無限記憶。完整問題、最近對話和目前路線都要分開看。

**第二段：換路後回來。**

學習進度可以想成幾個欄位：哪條路線、哪個階段、答過什麼題，以及是否符合解鎖條件。換一條路，不應該蓋掉原本那條。返回時由程式讀出進度，不是讓模型憑語氣猜我上次學到哪裡。

舊按鈕也是一種情境。昨天的題目還留在聊天室，但今天是新場次；按到昨天的答案，不能亂改今天的分數。所以測試要包含返回、退出和過期，不能只看第一次打開正常。

**第三段：固定題為什麼不用模型判。**

固定試煉的題幹、選項和正解已存在資料裡。使用者作答之後，程式比對答案，顯示對應解說。沒有必要每次再請模型重新決定標準答案。

但固定不等於一定寫對。如果題目有兩個合理選項，或者解說引用的來源不支持它，就還是要修。程式檢查、科學內容審核和模型回答測試是不同的事，後面會再說這個區別。

## P17｜後端其實怎麼走？

### 講稿

剛剛看的是手機端。

後面大概是這樣。

LINE 把訊息送到 Webhook。

伺服器先驗證 LINE 的簽章，確定不是隨便有人偽造一包資料丟進來。

最後再透過 LINE Reply API 回去。

中間還有事件去重和排程，主要是避免同一件事被重複處理，或同一個人連續按幾次把狀態弄亂。

# 老師可能會問

## 1. 為什麼不用 ChatGPT 就好？

一般聊天 AI 可以聊更廣的題材，我這個專題做的是 LINE 串接、自己的知識範圍、固定題庫、導引學習和進度保存。

不是要證明我的 Bot 比 ChatGPT 聰明。

## 2. 有自己訓練模型嗎？

沒有。

模型用現成 API。

我做的是資料、流程、題庫、LINE 串接、角色設定和學習狀態。

## 3. 1001 是什麼意思？

是我早期替正式題目和知識卡設定的總量上限，不是一千零一個資料庫。

為什麼 1001？

因為《一千零一夜》。

真的就這樣。後來內容繼續擴充，目前已經是 1236 張知識卡和 300 道固定題，所以 1001 只保留成開發過程中的彩蛋。

## 4. 為什麼用 Gemma？

最現實的理由是這次有免費額度，而且當時課程 OpenAI 額度不夠。

系統本身可以換供應商，之後要換也不用重寫全部程式。

## 5. 你怎麼知道內容是對的？

固定資料保留來源，也需要人工和程式檢查。

但我不會說完全不會錯。

AI 可能錯，題庫也可能是人寫錯。

所以找到錯誤就要修。有來源編號也不代表那份來源真的支持回答，還要回去看內容。

## 6. 這算 RAG 嗎？

舊版比較接近本機知識卡匹配，再把需要的內容交給模型。

有沒有向量資料庫，要看最後交付版本實際怎麼做。

我會直接說怎麼找資料，不用一個架構名稱代替實作說明。

## 7. NAS 上線了嗎？

依上台當天狀況回答。

還沒：
「目前展示用的是已經測過的電腦環境，NAS 還沒有完成最後驗收。」

已經：
「目前已經搬到 NAS，這次展示也是用那個環境；但我只敢說目前測試正常，不會說永遠不會斷。」

## 8. 都是 AI 幫你做的嗎？

AI 幫很多。

程式和整理資料都有用。

不過題目要做什麼、哪些內容我覺得不好玩、哪裡要再補、最後要保留什麼，這些是我自己一路測出來的。

而且 AI 做完的東西還是要自己玩過，才知道有沒有哪裡怪怪的。

## 9. 沒有模型額度是不是都不能用？

開發工具和機器人的模型 API 是分開的。固定題庫與教材不需要生成模型，但 LINE、伺服器和網路仍然要正常，不是離線遊戲。

## 10. 為什麼沒有準確率？

要先定義測的是路由分類、回答內容，還是程式規則。沒有合適、帶標註的同版本資料，就不能補一個百分比；單元測試通過數也不是模型準確率。

## 11. 人類光合作用的數字是真的嗎？

是投影片列出的假設算出來的，不是人體試驗。受光面積、時間、輻照度和淨效率改變，結果也會改變。

## 12. 報告完會繼續更新嗎？

還不確定會不會一直用。我會先看自己或其他人實際遇到什麼問題，再決定要改什麼，沒有先承諾固定更新或繼續加到兩千題。

## P18：同一張卡可以用在哪裡？

例如白色草地的知識卡，可以解釋反射和吸收；教材用短一點的說法带人讀；理解題則問「看起來白色，是否就代表所有波段都不吸收？」同一個概念重用，不需要複製成十張卡。但內容修正之後，引用它的題目和教材也要一起檢查。
