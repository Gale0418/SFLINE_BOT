# 1. 我為什麼做這個

其實沒有很複雜的理由。

我喜歡天文，也喜歡科幻。

平常看到有趣的東西，我會想繼續往下問。晚上看到一顆很亮的星，會想知道它是什麼；玩《無人深空》看到橘色草地和白色草地，也會開始想：如果不是遊戲，這種植物到底能不能存在？

所以最初只是想做一個 LINE 天文問答機器人。

LINE 的好處很直接：不用再裝一個 App，也不用另外學介面。打開聊天室就能問。課堂上本來就有教 LINE Bot、Webhook 與 ngrok，我是在那個基礎上繼續加自己想要的內容。

後來會膨脹成現在這樣，主要不是因為一開始規劃得很大，而是自己測的時候一直遇到：

「這個我想問，但它不知道。」

於是就一路補下去了。

# 2. 系統現在可以做什麼

目前設計大致分成三種用法。

## 2.1 直接問

使用者可以直接輸入自然語言問題。

例如：
- 啟明星和長庚星為什麼是同一顆？
- 黑洞會不會蒸發？
- 白色草地怎麼做光合作用？
- 沒有超光速通訊，十光年外的殖民地怎麼聯絡？

能由本機知識卡高信心回答的問題，就直接使用本機資料；其他問題才交給設定的模型服務。

## 2.2 固定試煉

挑戰模式使用固定題庫。

題目、選項、答案與解說都先寫好，不讓生成模型每次臨時決定標準答案。

這樣做的理由很單純：同一題不應該今天答案是 A，明天又變成 C。

## 2.3 導引式學習

如果使用者不知道要從哪裡問，可以進入導引式學習。

基本流程是：

短講 → 理解題 → 幾段之後的複習挑戰 → 下一階段

不同路線的進度分開保存，使用者可以今天學一點，之後切到其他主題，再回來繼續。

# 3. 為什麼變成 1001

原本只打算做幾百題。

真正開始自己測之後，我曾經問機器人：

「你知道 1910 年哈雷彗星來的時候，曾經出現末日恐慌嗎？」

它答不出來。

我又問：

「你知道卡爾薩根是誰嗎？」

還是答不出來。

這兩個問題不代表系統一定應該知道全世界所有事情，但它讓我發現，自己真的會想聊的內容還很多。

於是範圍開始從天文基礎，擴到天文史、觀星、臺灣在地科普、異星生命、太空工程、科幻技術，最後甚至一路延伸到星際文明。

新版把「正式測驗題 + 正式知識卡」的總量上限設成 1001。

不是因為有什麼很深的理論。

只是因為想到《一千零一夜》，覺得 1001 這個數字比 1000 有趣，所以就用了。

這個數字是上限，不是 KPI。

重複題要刪，近似題可以合併；同一張知識卡能支援很多種自然問法，也不應該因此算成很多張卡。

# 4. 內容怎麼分

內容仍然沿用四座寶庫的方向。

| 寶庫 | 主要內容 |
|---|---|
| 星海之庫 | 肉眼星空、星等、行星、恆星、系外行星、觀測 |
| 地脈與生命 | 地球、生態、生命起源、異星生命、植物顏色 |
| 萬象法則 | 光、熱、物質、相對論、量子、能源 |
| 未來幻夢 | AI、太空工程、後人類、星際航行、科幻技術 |

這些分類只是入口，不是完全分開的四個箱子。

例如「白色草地」同時會碰到：
- 光的反射與吸收
- 色素
- 恆星光譜
- 生物能量
- 異星環境

而「星際文明」也不只是科幻設定，它會一路牽涉到：
- 生命維持
- 能源
- 工業維修
- 通訊延遲
- 長期自主運作

# 5. 臺灣在地內容

新版補了不少臺灣在地資訊。

內容包括：
- 臺北市立天文科學教育館
- 國立臺灣科學教育館
- 國立自然科學博物館
- 南瀛天文館
- 研究型與教育型天文台
- 合歡山暗空
- 光害與觀星條件
- 臺灣能取得的科普雜誌，例如《科學人》與《HOW IT WORKS 知識大圖解》

這類資料最容易出現兩個問題。

第一個是名稱很像。

臺北有臺北天文館，也有國立臺灣科學教育館；國立自然科學博物館則是在臺中。不能全部混成「臺北科博館」。

第二個是時效性。

例如今晚適不適合看流星雨，不能只靠一張知識卡回答。還要看：
- 雲量
- 月光
- 天空亮度
- 輻射點高度
- 道路與安全狀況

沒有即時資料時，系統就應該說沒有，而不是硬猜。

# 6. 我最喜歡的內容：異星植物顏色

我在《無人深空》裡最喜歡橘色草地與白色草地，所以新版乾脆把主要顏色都整理進去。

包含：
- 綠
- 黃
- 橘
- 紅
- 紫
- 洋紅
- 藍
- 青
- 棕
- 黑
- 白
- 灰／銀
- 多色
- 虹彩
- 季節性變色

重點不是「每個顏色都找一個理由說可以」。

真正要看的是：

1. 它反射哪些波段？
2. 它吸收哪些波段？
3. 光從什麼恆星來？
4. 大氣和水會留下哪些光？
5. 吸收到的能量夠不夠？
6. 顏色是色素造成，還是結構造成？
7. 有沒有其他營養來源？

白色草地特別適合拿來測。

因為看起來很白，通常代表很多可見光被反射。

這時不能只說「外星生物什麼都有可能」。

要繼續問：
- 是不是表面白，但下層仍吸收光？
- 有沒有利用其他可用波段？
- 是否有共生或混合營養？
- 剩下的淨能量到底夠不夠？

# 7. 科幻設定也可以拿來算

我不太想把科幻內容做成劇情問答。

比較有趣的是：

「這個設定如果放到現實物理裡，卡在哪裡？」

例如《銀河騎士傳》的人類光合作用。

可以先做一個簡單的量級估算。

假設：
- 有效受光面積：1 m²
- 光照：1000 W/m²
- 連續 6 小時
- 淨效率：5%

則：

E = 1000 × 1 × 6 × 3600 × 0.05

約為 1,080,000 J，也就是大約 258 kcal。

如果拿每天 2000 kcal 當比較基準，大約 13%。

這只是一組教學假設，不是人體實驗結果。

它比較像是在說：

即使把條件設得很友善，光合作用也比較像補充能量，不太像完全不用吃飯。

而且蛋白質、礦物質與其他身體材料也不會因為曬太陽就自動出現。

# 8. 從火星到銀河文明

新版有一條很長的導引路線：

地球  
→ 月球／火星基地  
→ 自給自足  
→ 太空工業  
→ 星際航行  
→ 跨星系通訊  
→ 長期自主殖民  
→ 銀河文明

這裡我刻意少談現實政治。

比較關心的是技術條件。

例如：
- 火星基地如果很久才補給一次，要自己生產什麼？
- 設備壞了，哪些零件一定要自己做？
- 如果兩個據點相隔十光年，沒有超光速通訊，一封訊息要多久？
- 沒有即時命令時，遠方系統要有多少自主性？
- 工業、能源與散熱能不能維持很多年？

「銀河帝國」在這裡比較像一個有點誇張的終點。

真的走到那裡之前，先把氧氣、供電、維修和通訊處理好比較實際。

# 9. 系統架構

整體流程大致是：

LINE 使用者  
→ LINE Messaging API  
→ HTTPS Webhook  
→ Flask  
→ 簽章驗證  
→ 事件排程與去重  
→ 指令／試煉／導引／自由問答  
→ 本機資料或模型  
→ LINE Reply API

LINE 事件進來之後，先驗證簽章，不直接相信收到的內容。

同一個事件如果被重送，系統會避免重複處理。

明確指令交給程式；固定題目也交給程式。

只有需要生成式回答的問題，才會送給模型。

# 10. 模型供應商

系統支援不同模型供應商。

開發過程中原本考慮 OpenAI，後來因為課程 API 額度不足，改用 Google AI Studio 的 Gemma 路徑。

最現實的理由就是：

免費，而且方便繼續測試。

另外，系統不會在設定成 Google 時，因為 Google 失敗就偷偷改用另一個付費服務。

這是為了避免「本來以為免費，最後默默燒錢」。

模型型號與實際 API 設定，正式報告時以當天交付版本為準。

# 11. 進度與資料保存

學習進度放在伺服器端 SQLite。

LINE 手機不直接操作資料庫。

系統需要記得：
- 使用者在哪條路線
- 目前哪個階段
- 哪些題已完成
- 是否符合解鎖條件

這些狀態由程式管理，不交給模型自由猜。

聊天歷史則是另一件事。

「記得學到哪裡」不等於「永遠記得全部聊天內容」。

---

# 12. 測試

目前需要分開看幾種測試。

## 12.1 程式流程

例如：
- LINE 簽章
- 重複事件
- 指令路由
- 題庫答案
- 按鈕狀態
- 學習進度

這類測試是在確認程式有沒有照規則運作。

## 12.2 科學內容

另外還要檢查：
- 題目有沒有寫錯
- 來源是否真的支持答案
- 科幻設定有沒有被誤寫成現實
- 同義題是否重複
- 易變資訊是否過期

## 12.3 模型回答

模型回答又是另一層。

格式正確，不代表內容正確。

如果未來要報 Accuracy、Precision、Recall、F1，也應該先定義到底在測哪個分類任務，再準備有標註的測試集。

不能拿「單元測試通過幾個」去冒充模型準確率。

# 13. 這次最大的困難

如果要說真正遇到的困難，我覺得不是某一個技術完全做不出來。

現在有 Codex、Astra 等工具，很多程式問題都可以加速處理。

真正麻煩的是：

做完之後一直覺得還可以再加一點。

原本幾百題就可以交。

後來問到哈雷彗星，不夠。

問到卡爾薩根，又不夠。

再想到臺灣觀星。

再想到植物顏色。

再想到科幻工程。

最後就一路長到銀河文明。

所以這次學到的一件事，反而是什麼時候要停。

# 14. 限制

目前仍有幾個很實際的限制。

1. 知識庫不是完整百科。
2. 本機匹配可能判錯。
3. 模型可能答錯。
4. 固定題庫也可能有人為錯誤。
5. 即時天氣、活動與開館資訊需要即時來源。
6. 伺服器上線不代表永遠不會斷。
7. 有導引式學習，不等於已經證明學習效果變好。

如果之後真的繼續做，應該先看實際使用者在哪裡撞牆，再決定要補什麼。

不需要因為還能生成，就繼續往兩千題衝。

# 15. 結論

永恆北極星原本只是一個 LINE 天文 FAQ。

後來變成：
- 自由問答
- 固定試煉
- 導引式學習
- 臺灣觀星
- 異星生命
- 科幻工程
- 一路延伸到銀河文明

最重要的不是題目很多。

而是我自己打開來測的時候，不會每問兩句就覺得「這裡怎麼也沒有」。

至於它是不是適合小朋友、是不是能真的提高學習效果，還需要實際找人使用之後才知道。

目前最確定的使用者，就是我自己。
