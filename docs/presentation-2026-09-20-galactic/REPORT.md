## 摘要

永恆北極星是一個以 LINE 為入口的科學問答與學習機器人。使用者可以直接提問、進行固定答案試煉，或沿著四座寶庫逐步學習。系統的目的不是提供無所不知的聊天介面，而是把零散好奇心串成可追問、可查證、能保留進度的探索路線。

千題級版本以「從肉眼星空一路走到星際文明」為內容主軸，包含臺灣觀星、天文基礎、異星生態、物理與能源、太空工程及科幻技術拆解。正式測驗題與正式知識卡合計上限為 1001 個內容單元；導引教材重用既有內容，不以同義問法與重複段落灌水。本文以橘色與白色草原、人類光合作用、火星基地到銀河文明三個案例，說明如何把興趣转化為科學問題。

技術上保留原有的本機知識卡優先、模型補助、LINE Webhook 簽章驗證、事件排程與去重、固定答案評分及伺服器端學習進度。驗證分為程式規則、內容正確性、模型回答、效能與教學成效五個層次，避免把「測試通過」誤寫成「回答永遠正確」。

# 第 1 章　背景、動機與研究目的

## 1.1 從一個問題開始，而不是從一份課綱開始

原始簡報用「看見冥王星的愛心，接著追問它為何如此」說明動機。[V6，P3] 新版延續這條思路，但把入口擴大到生活、遊戲和動畫：夜空中最亮的星是什麼？《無人深空》的橘色與白色草地能不能存在？《銀河騎士傳》讓人類光合作用，需要跨過哪些生物與能源障礙？

這些問題看似相距很遠，卻都可以拆成可學習的概念。草地顏色牽涉光譜與色素，光合作用牽涉能量收支，星際文明則牽涉通訊延遲、封閉生態和工業維修。專題要保留這種跳躍的好奇心，同時讓每一步有來源、有前提，不把想像直接當成科學事實。

## 1.2 三個具體目標

第一，讓使用者不必離開 LINE 就能開始提問或學習。第二，把回答、固定答案試煉與導引教材放進同一個對話入口。第三，清楚区分觀測事實、理論與工程外推、作品設定、文化故事，以及目前無法回答的內容。

「讓人願意繼續問」是設計目標，不是已經證明的學習成果。本專題未以實際學生研究證明成績、留存率或學習動機提升。

## 1.3 不做的事

本版不以現實政治衝突為主題，不評選政治體制優劣；涉及銀河文明時，只把制度當作通訊與協調的設定背景。哲學保留生命、人格、長壽、數位自我等邊界問題，不轉成人類紛爭的長篇辯論。

不宣稱自行訓練基礎模型，不將本機模型 API 呼叫描述成在 NAS 上跑大型模型，也不把沒有即時資料的回答當成天氣預報、當日開館保證或最新研究結論。

# 第 4 章　特色內容與科學案例

## 4.1 臺灣在地觀星：回答問題，也教人判斷

在地內容包含科普讀物、科學館、天文館、教育與研究型天文台、暗空環境及肉眼觀星。要先處理名字混淆：臺北的科教館、臺北天文館與臺中的國立自然科學博物館不是同一個機構；研究天文台也不能一律當作隨時開放的觀光景點。[R11][R12][R13]

《科學人》和《HOW IT WORKS 知識大圖解》可以作為延伸閱讀入口，而不是整本複製進題庫。出版刊期、訂閱方式與館藏須附查證日期；讀者應經出版者、合法平台或圖書館取得。以 2026 年 9 月為例，《科學人》官方網站列出的當期主題包含 AI 與自動化實驗室，適合作為「AI 如何參與科學」的研究入口，不據此捏造本專題已具備自主研究能力。[R14]

合歡山於 2019 年獲指定為國際暗空公園；這是有官方資料的認證，不是「今天一定看得到銀河」的保證。[R6] 流星雨觀測應一起考量月光、雲量、天空遮蔽、輻射點高度與安全可達性。没有即時天氣與道路資料時，機器人只能提供判斷方法及官方查詢入口，不宣布今晚哪裡最好。

星等、古代亮星、長庚與啟明、星座與星宿分成循序小單元。肉眼可見星數不給一個假裝全臺通用的固定答案；地點、季節、天空亮度、視力與是否暗適應，都會改變實際觀測。

## 4.2 異星植物：不是把地球的綠色換掉

NASA 的研究指出，光合生物的可觀測顏色可能取決於恆星光譜、抵達表面的光與生物色素，不必與地球陸地植被相同。[R3][R4] 但「外觀是某個顏色」不能唯一反推出色素、可用波段或恆星種類；入射光、大氣、水、反射、穿透、結構與觀看角度都會介入。

下表是千題版的**色族策展與合理性推演**，不是已發現外星草原的清單，也不是引用機構替每一色提供的認證。它把已有的光合作用與光學背景，轉成應該查驗的條件。

| 色族 | 可以研究的形成機制 | 必須回答的限制 |
|---|---|---|
| 綠 | 葉綠素類吸收與反射 | 地球上的常見結果，不是宇宙唯一解 |
| 黃 | 色素比例、覆蓋層與季節變化 | 變黃的外觀不等於能高效率養活全年生態 |
| 橘 | 類胡蘿蔔素等輔助色素；色素層覆蓋 | 可見的橘色不等於只吸收橘光；需保留淨能量收入 |
| 紅 | 色素保護、不同光合生物的組合 | 必須區分吸收、保護與外观，不照搬紅矮星配紅草 |
| 紫 | 不同光合色素與微生物生態 | 紫色微生物不是直接等於高等陸生植物 |
| 洋紅 | 多種反射與吸收特性疊合 | 人眼感到的混合色沒有唯一對應的吸收曲線 |
| 藍 | 色素或結構色 | 保留外觀所需反射後，哪些波段仍能供能 |
| 青 | 多色素與照明共同作用 | 水下與地面光環境不可混為一談 |
| 棕 | 色素混合、保護層或生態組成 | 棕色可能來自非光合部分，不能只看顏色判活性 |
| 黑／極深色 | 廣波段吸收 | 吸收更多能量也可能增加散熱與光損傷問題 |
| 白 | 毛狀、蠟質或散射表層；下層吸收 | 反射與穿透後剩多少可用能量，不能憑白色直接定罪或放行 |
| 灰／銀 | 表面微結構與部分反射 | 要量測淨吸收，不把金屬感誤當真正金屬組織 |
| 多色 | 不同器官、物種、共生層或功能分區 | 各部位的成本收益不同，不能把每一色都當獨立植物 |
| 虹彩／結構色 | 微結構干涉與角度依賴反射 | 外觀隨角度變，不能用單張圖片當固定光譜 |
| 季節變色 | 色素、保護與生命週期改變 | 季節呈白或橘，與全年維持同色的代謝要求不同 |
| 近透明 | 低可見光吸收、薄組織或稀疏色素 | 仍要找到實際吸收與代謝來源，不能以透明逃過能量守恆 |

白色草原是刻意保留的困難案例。表面大量反射可見光，通常會降低該部分可供吸收的能量；但仍須檢查是否有穿透到下層、使用其他波段，或由共生／混合營養補充。這些是附帶條件的模型，並不代表「白草一定能活」。遠紅光光合作用已有特定生物研究，但不能把它誇大成任何紅外線都能無限制供能。[R5]

## 4.3 《銀河騎士傳》的人類光合作用：先算能量

MBS 官方作品用語介紹記載，船員經基因操作能進行光合作用，因而約每週攝食一次。[R7] 這是**作品設定**，不是人體改造已可實現的科學結論。本專題借用它作為提問起點，不以劇情摘要替代分析。

以下做一個明示假設的量級估算：

- 有效受光投影面積 A＝1 平方公尺，不是把整個人體表面積都算成同時正對太陽。
- 入射照度 I＝1000 W/m²，假設持續 6 小時。這是樂觀的教學情境，不是任何地點的每日實測。
- 入射能量轉成可用化學能的淨效率 η＝5%，純粹用來估算，不宣稱改造人體已達成此效率。
- 為方便比较，以每日 2000 kcal 作為假設能量需求，不作個人飲食建議。

`E = I × A × t × η`

`= 1000 × 1 × (6 × 3600) × 0.05`

`= 1,080,000 J ≈ 258 kcal ≈ 假設每日需求的 13%`

即使先給出這組偏有利條件，結果仍較接近補充能源，而不是完全不用吃飯。提高效率、增加受光面積、降低代謝或增加共生系統，可能改變計算，但都需重新交代限制。缺少的蛋白質、礦物質、維修原料和代謝調節，也不會被「有陽光」自動解決。

若在封閉星艦內用燈照人，還要追問燈的電從哪裡來。這是能量轉換與循環的一部分，不是新增免費能源。若換成較大面積的藻類培養與食物系統，才有另一套可比較的工程問題。

## 4.4 從火星到銀河文明：把霸業拆成工程

「銀河帝國」在這裡是探索路線的幽默終點，不是政治主張。路線依序處理：生存、移動、供能、工業維修、通訊及長期自主運作。每前進一步，都問還缺哪些物理條件，而不是直接跳到統治整個宇宙。

光年是光在一年內走過的距離。[R8] 因此假設兩個據點相隔 10 光年，在沒有超光速通訊的情況下，單程訊息至少需要約 10 年；即刻回信的往返也要約 20 年。這是距離與訊號速度的計算，不是對某種制度的評價。

同樣必須區分恆星系與星系：跨越兩個恆星系，與離開銀河系到另一個星系，不是相同尺度。曲速與蟲洞可以作為理論或科幻分支，但「有數學描述」不等於已有可建造的引擎。

延伸題可比較世代船、休眠、機器探測、自主工業、巨型集能結構與數位生命的條件，不替尚未證明的技術背書。行星拆解則以採礦、能量與回收成本為問題，避免把「炸碎」當成自動完成資源收集。

# 第 5 章　系統設計與實作方法

## 5.1 訊息路徑

```text
LINE 使用者
  → LINE 平台
  → HTTPS Webhook／開發期通道
  → Flask：先驗證原始請求簽章
  → 有界事件排程

  → 指令／試煉／導引／自由問答路由

```

LINE 官方要求先驗證來源與內容完整性，並建議非同步處理事件。[R1][R2] GitHub 基準版採原子批次入列，容量不足回 503，接受後回 200 再由背景工作處理。[G1] 順序保證應限於伺服器接受事件後的排程，不宣稱能修復外部網路所有亂序。

快速回 200 也不等於工作已經持久化。記憶體佇列仍有程序中止後遺失的風險；不能把 ACK 或去重稱為完整的可靠訊息佇列。

## 5.2 本機回答與模型回答

規則能處理的指令由程式處理；高信心且有支持內容的問題走本機知識卡；其餘交由設定的模型服務補助。原始專案採 Google 或 OpenAI 供應商設定，不在執行途中默默跨供應商切到另一個付費服務。[G1]

模型輸出需符合程式契約，但 JSON 格式正確只代表能解析，不代表科學正確。來源 ID 存在也不保證該來源真的支持回答；這必須另做內容查核。

千題級資料不應被描述成「每次一千題全部塞給模型」。本報告不替未讀取的新版虛構向量檢索或新的檢索演算法；最後的上下文選擇方式應以交付程式說明。原基準版沒有向量資料庫與自行訓練模型。[G1]

## 5.3 導引學習與進度

原 v6 的設計為四条獨立路線，每條四個階段；每階段五段短講與理解題，之後五題複習挑戰需答對至少四題才解鎖下一階段。[V6，P8；逐頁稿第8頁] 千題版沿用這種「說明—理解—複習—前進」的機制，教材內容可以重新策展，不強迫為了增加題數增加關卡。

學習進度由伺服器 SQLite 保存；使用者的 LINE 手機不直接讀寫資料庫。[V6，P5、P8] 進度與聊天歷史是不同資料：記得學到哪一階段，不代表模型永久記得所有曾經聊過的事情。原稿的短期聊天記憶是最近三組對話；長路線需要明確主題與進度，不能宣稱無限上下文。[V6，P7]

## 5.4 安全、成本與部署

安全設計包含簽章驗證、事件 ID 去重、答題按鈕的 HMAC 與場次綁定。使用加鹽雜湊作為內部識別是降低原始 ID 暴露的假名化，不是完整匿名，也不是可逆加密。[V6，P5、P9][G1]

固定題庫與導引教材不呼叫生成模型，不等於 LINE 可以離線使用；LINE、伺服器、網路與外部服務仍有各自成本及故障可能。

部署主機可以從開發電腦遷移至作者持續開機的 NAS，但本報告不宣稱 NAS 已經上線。公開 HTTPS 入口、程序重啟、SQLite 資料保存與備份，均應獨立驗證。搬主機本身不會增加模型能力，也不會自動變成全天候服務保證。

# 第 6 章　測試、效能與驗證

## 6.1 五層驗證，不混成一個分數

| 層次 | 需要的證據 | 不能據此宣稱 |
|---|---|---|
| 程式規則 | 同一版本的單元／整合測試紀錄 | 所有科學答案皆正確 |
| 內容資料 | 題卡結構、去重、來源及固定答案審核 | 模型不會誤用來源 |
| 模型回答 | 固定測試集、標準判準、人工檢查 | 通過少量題就通過所有場景 |
| 效能與穩定性 | 環境、樣本數、延遲、錯誤與端到端紀錄 | 永久可用、零故障 |
| 學習成效 | 適當研究設計、前後測或比較資料 | 功能做好就代表學生學得更好 |

## 6.2 必要測試情境

入口測試檢查正確簽章、缺失簽章及偽造請求。事件測試檢查重送、同一使用者連續操作與容量不足。功能測試檢查幫助、挑戰、退出、分數、一般問答、學習換路與返回。狀態測試檢查完成解鎖、答錯後回饋、過期按鈕與資料庫交易。

內容測試特別使用容易混淆的邊界：白色草地不是白矮星；啟明與長庚需要同一核心概念；科幻人類光合作用不能被標記成已實現；查不到今晚天氣時，不應給確定觀測地點。

## 6.3 分類指標與回答正確率

若課程要求混淆矩陣或 Accuracy、Precision、Recall、F1，應建立有明確標註的「路由／事實層級分類」測試集，再分別计算。題庫有幾題、程式通過幾項測試，都不能拿來冒充模型分類表現。

- Accuracy：分類正確樣本數／全部樣本數。
- Precision、Recall、F1：依指定類別及平均方式報告，附上樣本數與混淆矩陣。
- 回答事實正確率：另以有標準依據的問題集評估，並報告不知道、無法判定與錯誤案例。
- 延遲：分開記錄本機、模型和完整 LINE 端到端路徑；報告中位數及適當分位數，不只挑最快的一次。

這裡提供方法，不提供虛構分數。原 v6 記載的 2026-09-08 四次真實聊天測試，僅能列作該日期的歷史連線紀錄。[V6，P9]

# 第 7 章　成果展示、限制與後續工作

## 7.1 三段可獨立完成的展示

1. **橘色與白色草原**：由遊戲景觀出發，檢查回答是否能講出吸收／反射、可用波段及限制，而不只給一句可以。
2. **火星到銀河文明**：用完整問題逐步跨越生存、工業與通訊，確認系統能守住現實／科幻分界，不宣稱無限記憶。
3. **導引換路与返回**：選路線、讀短講、回答一道理解題，再切換與返回；完整階段解鎖用事先錄好的真實片段輔助，不讓觀眾等做完二十段教材。

所有流程圖與範例文字都應標記為「設計示例」。只有實際錄製或截取的 LINE 畫面才標為實機證據。現場卡住時，切換同版本錄影；若錄影也沒有，回到流程圖並說明這是示意，不演假回覆。

## 7.2 已知限制

知識庫是策展範圍，不是全世界知識。新題可能缺來源，舊來源可能過時；本機匹配可能誤判，模型也可能編造。固定題庫不會隨機改正解，但題目本身仍可能寫錯。SQLite 保存進度不等於整體服務已具備備援。完成軟體整合不等於證明科學教育成效。

## 7.3 後續優先順序

下一步優先整理真實失敗案例、縮短錯誤路由、提升來源品質、完成部署與備份，再做適度使用者評估。是否再擴題，應由缺口與維護能力決定，而不是因為還能再生成一批。

# 第 8 章　結論

永恆北極星的價值不只是題庫變大，而是讓同一個問題能有三條後續路徑：繼續問、開始學、試著答。作者以四座寶庫整理內容，用本機資料與模型分工降低不必要的生成，再用明確進度把零碎聊天轉成可繼續的探索。

從夜空、橘色草原到銀河文明，跨越的不是一連串炫目的名詞，而是光、能量、生命、距離與工程限制。本專題希望保留科幻的想像，也保留承認不知道的能力。

**銀河帝國先不急。先讓每一個問題，都有可信的下一步。**
