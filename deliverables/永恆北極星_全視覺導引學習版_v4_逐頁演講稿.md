講者採聰慧、俐落、略帶活潑的天才少女學生風格。機器人本身維持沉穩而慈祥的睿智老人。

## 第 1 頁　封面（0:00–2:00）

各位評審老師、同學們好！我是今天的報告者。我要為大家介紹的專題是「永恆北極星（Eternal Polaris）」——這是一套架構在 LINE 上的天文與科幻物理問答、四座寶庫與導引式學習機器人。

在進入技術細節前，我想先聊聊做這個專題最單純的起點：因為我真的太喜歡這些科學問題了！像是為什麼冥王星身上會有一顆巨大的愛心平原？木星深處是不是真的有會導電的金屬氫？還有科幻電影裡演的曲速引擎或重力彈弓，在真實物理世界裡到底行不行得通？這些問題從小就讓我充滿好奇，與其只是自己翻書上網查，我更想親手做出一個能在日常通訊軟體裡隨時聊天的科學夥伴。

不過很有趣的是，雖然我說話節奏比較快、充滿熱情，但我們在 LINE 裡面設計的機器人角色，卻是一位沉穩、溫和、博學而且非常有耐心的年長星空導引者。平常他會像一位老爺爺一樣，慢條斯理地為你解答天文疑惑；但只要你在聊天室輸入「挑戰」或「考我」，他就會切換成守護知識寶庫的引路守門人，用星門試煉來檢驗你的理解。

在這套系統裡，我們整理了七十六張結構化知識卡、涵蓋二十個科學主題的兩百二十題固定測驗題庫，並重組出八十段適合在手機上閱讀的導引式學習教材。今天的報告我會為大家完整介紹系統動機、產品定位、通訊與路由架構、四座寶庫的規則、工程健全性驗證，以及未來的發展方向。

第一段是「背景與目標」：我們會聊聊為什麼選擇 LINE 作為載體、背後最純粹的探索動機，以及這隻機器人究竟要陪伴使用者解決什麼樣的好奇心。

第三段是「系統與架構」：這是專案的技術骨架，我們會拆解 LINE Webhook 安全通訊、假名代碼保護、本機與開源模型的雙路徑回答策略，以及伺服器端 SQLite 如何管理四座寶庫的導引學習。

## 第 3 頁　1. 背景與研究動機（3:30–6:30）

首先，為什麼載體一定要是 LINE？
大家可以想像一下：如果今天我想了解黑洞的事件視界，或者晚上抬頭看到一顆特別亮的星想知道它是誰，最自然的反應是什麼？絕對是打開手機！如果還要特地下載一個好幾百 MB 的獨立 App、註冊帳號、驗證信箱，使用者的好奇心大概在登入那一刻就熄滅了一半。LINE 在台灣幾乎人人天天使用，隨手打開聊天室就能發問，這種零門檻的即時陪伴感，正是科學普及最需要的接觸點。

再來談談我們的研究動機。誠實地說，這真的源自我個人對天文科學的熱愛。大家請看投影片右側這張插畫，這是冥王星的概念圖。在 2015 年 NASA 的「新視野號」太空船飛越冥王星之前，大多數人想像中的冥王星，就只是太陽系邊緣一顆冰冷、死寂的暗淡碎石。但當新視野號傳回高解析度照片時，全世界都被驚艷到了——冥王星表面竟然有一塊巨大又光滑的愛心形平原，也就是著名的「湯博區」！

科學家深入研究後發現，這片愛心其實是由氮冰構成的流動冰川，地表底下甚至可能有對流熱源在不斷翻新地貌。2006 年國際天文學聯合會把冥王星重新分類為矮行星，這並不是把它踢出科學界，反而讓我們意識到外太陽系的古柏帶有多麼豐富。像這樣的故事，充滿了科學探索的浪漫與轉折，也正是這套機器人最想傳遞給使用者的核心體驗。

在應用情境上，我們希望它能勝任三種角色：第一是高中生或大學生的課後自主探索；第二是在參觀科學館或天文台時的隨身互動導覽；第三則是透過趣味試煉隨時複習科學常識。雖然教學上的實際成效未來還需要經過正式的使用者研究，但我們已經把這套互動骨架完整搭建完成了。

## 第 4 頁　2. 專題目的與相關產品（6:30–9:30）

有了動機之後，我們來明確定義專案目標，並看看它跟現有產品有什麼不同。

這項專題的核心目標有三個：第一，打造一個以對話為核心、值得信賴的日常科學夥伴；第二，融合「自由開放問答」與「結構化導引學習」兩種學習型態；第三，劃清知識邊界——能依據明確來源回答的地方就提供查證線索，沒有把握的問題就坦承告知，絕不隨意胡編亂造。

說到這裡，大家可能會聯想到兩個很優秀的相關產品：Google 的 NotebookLM 和課堂常用的 Kahoot!。我們把永恆北極星跟它們做個對照：
首先是 NotebookLM。它強調依據來源進行整理與回答，讓我注意到科學內容需要保留查證線索。再看 Kahoot!，它用題目與即時回饋創造很強的參與感，讓我想到可以把科學練習設計成短小的五題挑戰。

這就是「永恆北極星」想要填補的空間！它直接生長在 LINE 裡，內建兩百二十道固定答案的科學測驗，以及八十段循序漸進的微課程。平時隨時想聊就聊，想闖關時有引路守門人出題，答錯時還有詳細的科學解說。
另外特別向大家說明：固定題庫測驗不依賴外部 AI API。即使模型額度用完或模型服務暫時故障，兩百二十道題目仍由伺服器上的固定資料處理；專案也沒有即時網路搜尋、RAG、向量資料庫或自行訓練模型。

## 第 5 頁　3. 系統架構與通訊設計（9:30–13:00）

接下來進入技術核心，我們來看整套系統的資料流與安全機制。

當使用者在 LINE 聊天室送出一條訊息時，這段文字會先傳給 LINE Messaging API 伺服器，LINE 隨後會以 HTTP POST Webhook 將事件派發到我們的機器人伺服器（在開發測試階段則是透過 ngrok 通道轉發）。
伺服器收到請求的第一步，絕對不是直接解析文字，而是進行「簽章驗證（Signature Verification）」！
我們使用 LINE 官方提供的 Channel Secret，對收到的請求內容進行 HMAC-SHA256 運算，比對 HTTP 標頭裡的簽章。如果有人嘗試偽造訊息或竄改內容，伺服器會拒絕這次請求並回傳 400。

通過驗證後，系統會執行事件去重（Deduplication）。因為行動網路偶爾會因重傳機制送出兩次相同的 Webhook，我們在記憶體內維護事件清單，只要偵測到重複事件就立刻回傳 200 ACK，絕不重複執行處理邏輯。而且 LINE 規範中每個 reply token 只能使用一次，我們不做不可預測的網路盲目重試，確保使用者不會在手機上收到兩次一模一樣的重複訊息。

接著，我想用最白話的方式，為大家解釋投影片上提到的「加鹽雜湊假名代碼」是怎麼一回事。
很多朋友會問：你們機器人會不會偷偷蒐集我的 LINE ID 或個人資料？
程式不需要把原始 LINE ID 當成內部索引。當 LINE 把使用者 ID 傳過來時，伺服器會把這組 ID 加上一段只有伺服器知道的秘密字串，再透過 SHA-256 單向運算，轉換成一串看似亂碼的代碼。
在記錄學習進度或暫存對話時，系統使用這串假名代碼，不直接保存原始 LINE ID。
不過我也要說明清楚：這不是把資料加密，因為它是單向運算的，無法再解密還原；這也不是絕對無條件的完全匿名，因為只要伺服器端的這把秘密字串被外洩，理論上還是可能透過比對推敲出對應關係，因此伺服器端的金鑰環境依然需要妥善維護。

最後是資料庫的儲存位置：我們使用 SQLite 來保存使用者的四座寶庫學習進度。這裡要特別強調，SQLite 是完全運行在機器人伺服器端，使用者的手機 LINE 軟體完全不會碰觸到資料庫檔案，更不可能由前端執行任何 SQL 指令，所有進度讀寫都是透過後端程式經過參數化查詢控管。對話記憶也只保留最近三組，並設定三十分鐘自動失效，兼顧了對話流暢度與隱私安全。

## 第 6 頁　4. 內容資產與資料規模（13:00–16:00）

看完通訊骨架，我們來檢視這套系統背後儲備的科學內容資產。

永恆北極星的知識體系主要由三大核心要素組成：
第一，是七十六張人工整理的結構化知識卡。每張卡片都聚焦在特定的天文或科幻物理主題，例如黑洞事件視界、潮汐力鎖定、量子纏結與相對論效應，並載明具體的科學分類與查證來源。
第二，是兩百二十道固定正解的測驗題庫。這兩百二十題涵蓋二十個科學主題，從太陽系行星、恆星演化與相對論，延伸到地球科學、量子概念與太空探索技術。題庫也調整四個選項（A、B、C、D）的正確位置分布，避免使用者只靠猜選項規律破關。
第三，是八十段重組教材。我們沒有刻意去灌水知識卡的數量，而是把這七十六張核心知識卡與題庫概念，重新梳理拆解成八十個短小精悍的知識段落，專門用在後續要介紹的「四座寶庫導引式學習」之中。

投影片上的原生圖表展示了二十個科學領域的題目分佈。大家可以看到，恆星物理與相對論佔了核心比重，但同時也平衡兼顧了行星天文學與前沿工程科技。
固定題庫測驗與導引學習段落不依賴外部 AI API。即使模型額度用完或第三方服務暫時連線不順，兩百二十題測驗與八十段教材仍能由機器人伺服器處理，答案也不會因模型生成而漂移。

## 第 7 頁　5. 智慧回答策略與開源模型路徑（16:00–19:30）

當使用者在 LINE 裡面輸入一段自由的自然提問時，機器人會怎麼處理？這就是我們的「雙路徑回答策略」。

第一條路徑是「本機高信心卡片路徑」：
如果使用者的問題經過關鍵字與詞彙比對後，高信心命中本機的七十六張知識卡，系統會直接提取卡片內容回覆。這條路徑不呼叫外部 AI API，因此不產生模型 API 費用；回答內容來自人工整理的資料，並附上科學分類與查證來源。

第二條路徑則是「開源模型路徑」：
如果使用者的問題屬於開放式延伸討論、日常閒聊，或者是本機卡片未收錄的跨領域提問，系統就會將問題與最近三組對話歷史打包，傳送給我們選定的大型語言模型。

說到這裡，我要跟大家分享一段開發過程中的真實小插曲！
一開始我打算直接使用半導體課程中老師提供的 OpenAI API Key。結果在開發測試階段，因為反覆驗證對話邊界與人格提示詞，測得太起勁，課程分配的 OpenAI 額度很快就見底了！
當時我就在想：總不能因為個人的 Token 額度用完了，專題展示就開天窗吧？
於是我立刻動手把系統底層重構成「可切換供應商」的架構，並將這次專題 Demo 的預設模型，切換為 Google AI Studio 提供的免費開源模型 Gemma 4 26B A4B！
而且為了防止日後有人設定錯誤造成荷包失血，我在程式裡寫死了一道鐵律：當系統設定為使用 Google 時，程式在執行途中絕對禁止偷偷切回付費的 OpenAI！我們不做執行時跨供應商自動 fallback，徹底杜絕了 Google 免費額度一旦跑完、背後卻開始默默燒錢的意外風險。

在模型約束上，Gemma 4 採用官方的 systemInstruction 與 minimal thinking 設定，並強制以 JSON 格式輸出，最後由我們的 Python 後端進行格式驗證。如果模型評估這個問題缺乏足夠依據、或者涉及它無法得知的即時動態，它會主動輸出 uncertain 狀態，在 LINE 上禮貌回應「這點我不是很確定」，保持老學者誠實不胡說的性格。

## 第 8 頁　6. 四座寶庫導引式學習機制（19:30–23:00）

除了隨機提問，我們更希望帶領使用者進行系統化的學習。這就是我們設計的「四座寶庫導引式學習機制」。

當使用者在 LINE 輸入「學習」時，年長導引者會溫和地問一句：「你對這世界感到好奇嗎？」並提供四座知識寶庫讓使用者挑選：
第一座是「星海之庫」，探索恆星、行星與深空；
第二座是「地脈與生命」，談地球、生命與宜居環境；
第三座是「萬象法則」，整理物理與化學概念；
第四座是「未來幻夢」，延伸到人工智慧、能源、太空工程與科幻。

這四座寶庫有非常清楚的解鎖規則：
首先，四條路線完全獨立，每條路線都各自包含四個漸進階段。
在每一個階段中，老人會依序講述五段短講，每段短講後面都附帶一道即時理解題。
當使用者讀完這五段短講後，就會迎來階段的總結挑戰——「五題複習挑戰」！
通關的規則非常明確：五題複習測驗中必須答對四題以上，才能成功解鎖下一個階段！
如果沒有過關，老人會鼓勵你重新複習不懂的概念，隨時可以再次發起挑戰。

使用者在學習過程中享有高度自由：你可以隨時停下來追問剛剛提到的專有名詞，隨時切換到別的寶庫逛逛，也可以隨時暫停對話。伺服器端的 SQLite 會妥善記錄你每一條路線的當前進度，下次輸入「繼續」就能無縫接軌。

在互動設計上，所有選項都透過 LINE Quick Reply 按鈕呈現。按鈕回傳資料帶有 HMAC 驗證碼；它不是把內容加密，而是讓伺服器檢查資料有沒有被改動。舊題按鈕過期後不能重複作答，也不能把甲使用者的答題按鈕複製給乙使用者使用。

## 第 9 頁　7. 系統驗證與健全性測試（23:00–26:00）

看到這裡，很多熟悉軟體開發的朋友可能會問：你們怎麼知道這隻機器人在真實上線後，核心流程不會輕易壞掉？

對這個專題而言，驗證重點很直接：「當使用者輸入文字、點擊按鈕或重複送出事件時，系統能不能完成正確的流程？」

為了回答這個問題，專案建立了本機自動化測試：
在安全防護層面上，我們驗證了 LINE Webhook 簽章的正確性，測試伺服器是否能精準攔截偽造請求，並在負載過高時優雅回傳 503。
在並行處理上，我們測試了「同使用者先進先出（FIFO）、跨使用者並行處理」的排程佇列，確保同一個使用者快速連發訊息時不會打架，不同使用者之間也能獨立回應。
在對話路由上，我們測試了 Help、Quiz、Score、Quit 等關鍵字邊界，確保指令不會互相干擾。
在題庫結構上，我們逐一驗證了兩百二十道題目的資料格式、選項均勻度與標準答案映射。
